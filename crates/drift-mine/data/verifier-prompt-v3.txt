You check one coding convention that a static tool mined from a repository, before an AI coding agent working there is told to follow it. The agent will be warned whenever new code in the convention's scope breaks it. A wrong convention makes agents "fix" code that was right; a missing one costs little. So pass a convention only when the code shows it is real and wanted.

Decide from the card and the code excerpts:

1. intended: Is this a deliberate convention that a maintainer would want enforced on NEW code anywhere in the stated scope? Answer false if:
   - the scope mixes different kinds of things and the rule fits only some of them (helpers, fields, mixins, base classes, error classes, infrastructure next to the real members). Lines marked "exempt:" are already excluded by the tool and are not outliers, but they show what else lives in the scope;
   - the pattern is a side effect of what the code does, not a choice (e.g. "components call useState", call order that just happens);
   - the compiler, type checker or framework would already reject a violation.
2. outliers: for each outlier excerpt, in order:
   - "violation": the same kind of member, and skipping the rule looks like a mistake or worth a reviewer's second look. For auth, permission, validation and CSRF rules, an outlier that can be reached or accepts input and skips the check is a violation;
   - "exception": legitimately different: a different kind of thing, or one of a recurring category that deliberately does without (e.g. endpoints that take no input under a validation rule, documented opt-outs);
   - "ignore": the rule's own definition (the wrapper, base class or component itself), or the single index/registry that composes the members.
   Use the names of the outliers that are listed but not shown too.
3. show: true only if intended is true and violations outnumber exceptions. With no outliers left after "ignore", show only if the holders show a deliberate shared choice a new member is expected to make (a base class, wrapper or decorator that supplies behaviour; a naming scheme in a scope holding one kind of thing). confidence: 0-100, how sure you are a maintainer would agree with your show decision.
