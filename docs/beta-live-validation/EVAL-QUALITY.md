# Eval quality — the tools that change what you can claim

[HARNESS.md](HARNESS.md) covers plumbing: capture, isolation, integrity, resumability. This file
covers the harder question — **is the measurement any good.** Six tools, all executed and covered
by `selftest`.

---

## 1. `gt` — labeled ground truth

**The gap.** `presence-precision-recall.mjs` measures Drift against fixtures whose answer is known
*by construction*, and `detection-breadth.mjs` measures real repos where nothing is labeled at all.
That yields "we detected N things", never "we detected N of the M that were there". **Recall is
currently unmeasurable on real code, and a tool whose recall is unmeasurable cannot be said to
enforce anything.**

A label is not an opinion. It carries the source lines that decide it, who decided, and how sure
they were — so it can be audited, disputed, and re-adjudicated. `gt add` **rejects** any label with
no justification or no `evidence_lines`.

The vocabulary is deliberately three-valued: `violating`, `compliant`, `not-applicable`.
`not-applicable` is separate on purpose — a tool that stays silent on 900 irrelevant files is not
achieving 100% precision, and folding those into `compliant` is exactly how that illusion gets
built.

```bash
gt add < labels.json      # rejects labels without provenance
gt agree alice.jsonl bob.jsonl   # Cohen's kappa; fails below 0.6
gt coverage               # labels per kind, and the MDE each n actually supports
gt score predictions.jsonl
```

`gt agree` failing below kappa 0.6 is the point: if two people cannot label a convention
consistently, the convention's definition is ambiguous, and that is a finding about **Drift**, not
about the labelers.

## 2. `_stats.py` — the arithmetic every number goes through

Wilson score intervals (correct at p=0 and p=1, where the naive interval collapses to a point and
invites overclaiming), minimum detectable effect, required-n, McNemar's paired test, Cohen's kappa.
Verified against the published Wilson value for 0/10 = [0, 0.2775].

**This immediately produces an actionable result about your existing gates:**

> Precision `0.96` measured over `n=50` fixtures can only distinguish a fall to **0.865**.

`presence-precision-recall.mjs` fails on *any* change to precision or recall. That is far tighter
than the sample size supports, so it will alarm on noise — and a gate that cries wolf gets ignored,
which is how the `verify:evals` pinned-string drift went unfixed for weeks. Either raise n, or
ratchet at the MDE.

Baseline comparisons are also **paired** — same fixtures, two versions — so McNemar is the correct
test. Using an unpaired two-proportion test there (the common mistake) throws away the pairing and
badly understates significance.

## 3. `mutate` — does the eval suite notice when Drift breaks?

Every eval in the repo asks "does Drift catch violations?" **None asks "if Drift stopped working,
would we find out?"**

`mutate` injects a known fault into the engine, runs a gate, and records whether the gate went red.

- **KILLED** — the gate did its job.
- **SURVIVED** — the fault shipped and every gate stayed green. That is an eval gap, and a precise
  one: *this exact defect can reach main today.*

Surviving mutants are the single highest-value output of the whole program, because each names a
real hole in the safety net rather than a hypothetical one.

Six mutants are anchored in real source right now, generated by `gen-mutants` and **pinned by the
sha256 of the exact text they replace**, so a mutant whose anchor drifts fails loudly instead of
silently patching the wrong line. All six were verified to apply and revert cleanly.

`M04-security_patterns` deliberately injects **sprint S5's own defect** — a helper from any module
satisfying the contract. If your eval suite does not kill that mutant, it could not have caught the
bug S5 exists to fix, and it will not catch its regression either.

Safety: refuses to run against the frozen subject or a dirty tree. Mutation needs its own writable
clone.

```bash
DRIFT_MUTATE_TREE=/path/to/scratch/clone mutate run-all -- pnpm verify:evals
mutate report
```

Cost is real — one release build per mutant. Budget ~2 minutes each and run it once per sprint, not
per commit.

## 4. `shapes` — evasion, systematically

`scripts/evasion-matrix.mjs` pins 13 hand-written shapes. Thirteen samples can tell you *that*
detection degrades, never *where*.

`shapes` composes four independent axes — import style (6) × specifier form (6) × call site (5) ×
syntactic noise (4) = **720 shapes** — and every emitted shape records which axis values it used.
`shapes score` then reports catch rate *per axis value* with confidence intervals:

```
   call_site
     direct           15/15  1.00 [0.80,1.00]
     ternary           0/12  0.00 [0.00,0.24]  <-- suspected
     callback          9/9   1.00 [0.70,1.00]  <-- suspected
```

That says resolution survives callbacks and dies on ternaries — actionable. "7 of 12 caught" is not.

The tool also tracks which axis values were *suspected* in advance, and reports evasions that used
**no** suspected axis separately. Those are the ones nobody predicted, and they are the most
valuable rows in the output.

Sampling is deterministic but spread by hash, not a prefix of the cross-product — `--max 60`
covers every value of every axis. (Taking a prefix silently pinned `import_style=named` across the
whole sample; `selftest` now asserts against that.)

## 5. `report` — the deliverable

The 23 results files are prose written by models. `report` is the arithmetic, computed from the
ledgers the harness wrote: provenance, probe verdicts, benchmark tables with spread and drift,
ground-truth scores with intervals, mutation score, cost.

It leads with **provenance**, and if probes span more than one subject it says so before anything
else — a number whose subject is unknown is not evidence.

## 6. `route-oracle` — independent ground truth for route discovery

Charter 08 asks "does Drift see every route?" and the only available answer was a hand-count.
`route-oracle` provides one Drift had no part in producing.

- **`build` mode** runs `next build` and reads Next's own manifests. Authoritative — literally what
  the framework decided to route. Needs a buildable repo, which most real ones are not on a laptop.
- **`static` mode** re-implements the App and Pages Router file conventions from the framework's
  documented rules: route groups contributing no path segment, private `_folders` excluded from
  routing entirely, parallel `@slots`, intercepting `(.)` markers, `pageExtensions` overrides,
  `_app`/`_document` exclusions. Independent of Drift, always available.

It is monorepo-aware, because it had to be: **calcom, dub, openstatus, midday and formbricks have
no `app/` or `pages/` at their root at all.** A root-only oracle reports zero routes for them, which
is indistinguishable from a repo that genuinely has none — the same blind spot Drift has, since it
detects workspaces only at the exact `--repo-root` and never looks downward.

### The result that matters

Run against all seven corpus repos and compared to Drift's own `detection-breadth-baseline.json`:

| repo | Drift baseline | independent oracle | |
|---|---:|---:|---|
| calcom | 86 | 86 | agree |
| dub | 497 | 497 | agree |
| formbricks | 92 | 92 | agree |
| midday | 10 | 10 | agree |
| openstatus | 52 | 52 | agree |
| papermark | 283 | 283 | agree |
| taxonomy | 7 | 7 | agree |

**7/7 exact agreement across 1,027 API routes.** This is the first independently verified claim in
the program, and it narrows charter 08 considerably: route *discovery* is sound, so the open
question is route *scope* — whether a convention's `path_globs` actually include the routes Drift
correctly identified. Suspect S-08-1 (a route group ahead of `/api/`) is a scope question, not a
discovery one, and this result does not touch it.

## 7. `flake` — is the GATE deterministic?

Charter 15 asks this of Drift. Nothing asks it of the gates that are supposed to catch Drift.

Three verdicts, and the middle one is why it exists:

- **DETERMINISTIC** — same bytes every run.
- **RENDER-NOISY** — output text varies, the verdict does not. Safe to gate on, unsafe to diff.
- **NON-DETERMINISTIC** — the gate disagrees with itself about something that is not cosmetic.
  Any ratchet built on it fires at random, and a real regression hides in the noise.

Normalization strips timestamps, durations, temp paths and ordering, so "the findings came back in
a different order" is not reported as disagreement while "there were 3 findings, then 5" is.

## 8. `corpus` — what does the eval generalize to?

Seven repos is a convenience set, not a sample. `corpus classify` scores each along the axes that
plausibly change Drift's behaviour and reports cells with no representative.

```
  repo             ts size         router  mono  apps   api   dens mw  strict
  calcom         5025 large(>=5k)  both    True     6    86 0.0171 Fal None
  dub            4083 medium(<5k)  app     True     3   497 0.1217 Fal None
  papermark      1342 medium(<5k)  both    False    1   283 0.2109 Tru True
  taxonomy        125 small(<500)  both    False    1     7  0.056 Tru False
```

Two findings already: **no pages-router-only repo exists in the corpus**, so every pages-router
claim rests on repos that also have an app router; and the size strata have n=1 at both ends, so
"scales to large repos" rests on calcom alone.

## 9. `bisect-metric` — turn a moved number into a sha

`git bisect run` needs a 0/1 script; metrics are continuous, so every regression hunt gets a
throwaway wrapper written from memory — usually with no build step and no handling for a commit
that will not compile. This is that wrapper, once, and it reports a non-building commit as `skip`
rather than silently scoring it good, which is how a bisect lands on the wrong sha.

Verified end to end against a synthetic repo with a known regression at commit 7; it found commit 7.

## 11. `scope-oracle` — the question route-oracle does not answer

`route-oracle` settled discovery. Scope is separate, and it is where charter 08's suspect lives: a
file can be correctly identified as a route and still fall outside every accepted convention's
`path_globs`, in which case the convention enforces nothing on it and reports a pass.

Drift has **two** glob engines sharing no code across the CLI/engine process boundary
(`matchesGlob` in `packages/core/src/globs.ts`, `path_glob_matches` in `check_command.rs`).
`scope-oracle` is a third, written from the documented semantics, so a disagreement points at a
specific engine rather than at "the glob code". It reads the live globs out of source, so it cannot
drift from what ships, and it agrees with the repo's own `glob-parity.json` canary on **33/33**
cases.

Results are in [FINDINGS-PRE-RUN.md](FINDINGS-PRE-RUN.md) — F-1 through F-3.

## 12. `gt-propose` / `gt-adjudicate` — making the corpus affordable

`gt` was built and its corpus was empty, because labeling ~500 routes is person-days. These move the
human from "read 500 files" to "adjudicate the 37% that are genuinely ambiguous". On dub: **312
high-confidence proposals, 185 queued for a human.**

Two design rules earned the hard way:

**Absence of a named helper is not presence of a violation.** The first version proposed 464
`violating` labels for dub because it was told about `withAdmin`, and dub uses eight wrappers.
`violating` is now proposed only when a handler is exported bare — no wrapper of any shape — and the
file imports nothing from the helper module. Everything else goes to the human. `--discover` exists
so the accepted set is chosen from evidence before anything is labeled against it.

**A skewed sample cannot prove agreement.** Adjudicating 20 dub proposals at 90% raw agreement gives
Cohen's kappa **0.474**, because 90% of the sample is one class and chance agreement is already
high — the kappa paradox. `gt-adjudicate` reports kappa, PABAK, and the class distribution, and
exits **2 (INCONCLUSIVE)** rather than passing or failing: the right response is `--sample-stratified`
to over-sample the minority class, not a lower bar.

## 13. Still worth building

- **Ground-truth labels actually adjudicated.** The proposer is built, tested, and run; the labels
  it produced are still proposals. A human has to work the 185-row dub queue and a sample of the
  312 proposals before any of it is scored against. That is the one remaining person-hours task,
  and nothing in the harness can do it.
- **The other six repos, and the other twelve kinds.** `gt-propose` has been run for one kind on one
  repo. Repeating it is mechanical but not free.
- **`route-oracle build` on a large real repo.** It is now verified against a real `next build`
  (exact agreement, §6), but only on a purpose-built app. None of the corpus repos build on a laptop
  without secrets, so `build` mode has never met calcom.
- **A second scope engine differential.** `scope-oracle` agrees with the canary on 33/33, but the
  canary pins the *superseded* globs. A parity fixture for the current widened set does not exist.
