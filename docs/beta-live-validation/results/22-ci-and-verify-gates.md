### F-22-1 — `eval:external`/`eval:evasion`/`eval:presence`/`eval:bench` require a *writable* corpus, not a readable one — undocumented, discovered by accident

- **Expected:** the harness's own docs (`22-ci-and-verify-gates.md` §22 obs. 16, and `verify:evals`'s own package.json chain) frame the missing-in-CI gap as "no cloned corpus repos and no release engine binary" — implying a normal clone would suffice.

- **Blast radius:** anyone reproducing `verify:evals` locally against a read-only mirror (a CI cache, a network share, a Docker layer) will see this as an environment failure indistinguishable from a permissions misconfiguration, not as "these four scripts need a writable clone." This is a real, previously undocumented operational fact about what `verify:evals` costs to run for real (P-22-09's "quantify the cost" ask) — not predicted by any suspect-list entry.
