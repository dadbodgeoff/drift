TypeScript compiler), Drift has 0 disagreements, 0 resolution gaps and 100% export
recall, and recognises routes in Next.js, Express, NestJS, Hono and Fastify.**
The evaluation is codified: `node eval/run.mjs` clones every repo at its pinned
commit and fails on any regression (see [eval/README.md](../../eval/README.md)).

## Route conventions now learned

These are proposals from `drift census`, rated by the builder, not by independent
labellers:

- **immich:** routes are decorated with `@Authenticated()` (304/315); 273 of
  them pass a `permission`.
- **infisical:** routes are wrapped in `verifyAuth()` (1,550/1,702).
- **novu:** inbox routes are decorated with `@UseGuards` (36/37).

In midday the facts are now correct: 70 protected routes with a scope check, 1
protected route without one, and 43 public routes. No single convention covers
the folder because public and protected routers sit side by side. Expressing
"protected routes also check a scope" needs conditional (co-occurrence) rules,
which the plan schedules after launch.

## Known gaps

| Gap | Impact | Next step |
| --- | --- | --- |
| `this.service.method()` calls are not resolved | NestJS handler bodies lose service calls | Resolve constructor-injected properties through parameter types |
| Conditional rules ("if protected, then has a scope") | Mixed public/protected folders yield no route convention | Co-occurrence rules from the plan |
| Fastify shorthand inside plugins (`server.get(...)` on a parameter) | Only the `route({...})` form is found inside plugins | Treat plugin parameters typed as Fastify instances as routers |
| Middleware arrays imported from another file (`...protectedMiddleware`) appear as one name | Guard names are the array's name, not its members | Expand exported arrays through the linker |
