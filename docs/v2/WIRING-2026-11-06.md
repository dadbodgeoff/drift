# Wiring rules: "you added one, but didn't wire it up" (2026-11-06)

> **Dated record (2026-11-06).** This page records Drift as it was on that date and is
> kept as written, apart from this note and the removal of the builder's own precision estimates (below). It is not current documentation:
> behaviour, output and figures may have changed since. The [README](../../README.md)
> describes the current product, and its
> [Limits of the beta](../../README.md#limits-of-the-beta) gives the current
> precision figures and their sources in `eval/study/runs/`. Precision figures
> here are development-set figures under the tier and rubric of their date, and
> none is a held-out result. Under decision D7 the default tier is TypeScript
> call wrappers and layering only, Python advises only, and the default tier
> ships as advise until it measures ≥ 95% on a held-out set.

An agent adds a NestJS provider, a route, a Celery task or an env var. It compiles
and the tests pass, but it does nothing, because every sibling is also listed
somewhere the new one is not. This milestone teaches Drift to learn those lists and
to say exactly where the new member goes. It ships **experimental, suggestion tier,
off by default**.

```
[D-c796fc] classes in src/** (*.service files) are registered in Module() providers of src/app.module.ts (6/6)
  at   src/refunds/refunds.service.ts:4 RefundsService
  like src/billing/billing.service.ts#BillingService
  fix  add RefundsService to Module() providers in src/app.module.ts:10 (like BillingService, line 12)
```

## Turning it on

Use either of these. Without them, no wiring code runs, and every output is
byte-identical to before (verified on 22 dev repos; see Measurement).

- `.drift/config.yaml`: `experimental: [wiring]`. Unknown keys and unknown
  features are said on stderr (`unknown setting`, `unknown experimental feature`),
  never an error, so other tools' keys are harmless and a typo is visible. An
  `experimental` that is not a list is an error.
- `DRIFT_EXPERIMENTAL=wiring` in the environment (a comma-separated list).

**Off means off.** The flag gates mining *and* enforcement. With it off, wiring
conventions already in `.drift/conventions.yaml` are inert:
- `check` (text, JSON, SARIF) and PR mode skip them, with one stderr note
  (`N wiring convention(s) skipped: the experimental wiring feature is off`);
- the hooks and MCP skip them silently;
- `init` drops them, with a note.

So one person running `DRIFT_EXPERIMENTAL=wiring drift init` cannot turn wiring
checks on for their team or CI.

**Never blocks.** Wiring rules always advise, until they are blind-labelled. This
is enforced in three places: when the policy loads (a hand-set `mode: block` reads
as advise), in the check's effective mode, and in `drift review --block` (even
with `--force`).

## Rule kinds

Both kinds are outside the default tier's allowlist, so they are suggestions, and
they never block (see above).

| `rule.type` | Holds when | Mined from |
| --- | --- | --- |
| `registered_in` `{slot, path?, named?, reach?}` | the symbol is named by the list at `slot` in `path`, or by a list reachable from it (below). With no `path`, it is named by some list of the family `slot` (each `@Module`'s `providers`). `named` narrows to a name pattern (`*_JOB_DEFINITION`). `reach: true` says the rule was mined with members registered only in reachable lists, and the summary reads "…, directly or in the lists it reaches" | current facts |
| `mirrors_keys` `{from, to}` | every key of `from` is also in `to` | git history (co-change) |

## Registries

A registry is a place that names other code **by resolved reference**, never by
string. The parsers record it as a new fact, `FileFacts.registries` (facts
schema 9 after the merge train; 5 is #37, 6 to 8 are #49, #51, #53). Each entry has a `slot`, a `line`, and `items` of canonical targets
with lines. Targets go through the same resolution as calls and imports: aliases,
barrels and `export *` chains are followed.

| Slot | Example |
| --- | --- |
| `arg:<callee>@<i>[:<key>]` | `@Module({ providers: [...] })`, `combineReducers({ a, b })`, `createTRPCRouter({ x: xRouter })`, Python `Celery("p", include=[...])` (keyword index 99) |
| `binding:<name>` | `export const routes = [...]`, `urlpatterns = [...]` (also `+=` and `.extend`), `INSTALLED_APPS = [...]`, `export default {...}` |
| `calls:<receiver>` | `app.use(a); app.use(b)`, `admin.site.register(M)`, `program.addCommand(x())`, also in top-level factory functions |
| `exports` | a barrel: the file's exports when it has re-exports (from the existing export facts) |

Details:
- **One file's lists of one slot are one registry:** two `@Module`s in a file, or a
  tRPC router nested in another (`router({ a, key: router({ ... }) })`). They give
  one rule and one id, and the fix names the list that holds most of the role.
- A list naming another module-level list stands for that list's items, across
  files and through any depth (`providers: [...USE_CASES]`, `extra = [...dispute]`).
  A fix for such a list names the inner list nearest the member
  (`controllers: [...controllers]` sends you to `controllers/index.ts`).
- A spread of a constant with a literal value (no calls) adds and hides nothing.
- `forwardRef(() => X)` names `X`.
- Django `include("app.urls")` names that module.
- Python module paths written as strings directly in a list are resolved like
  imports: a module (`"proj.tasks"`), or a package (`"dcim"`, which registers the
  app's `apps.py` config, not every module in it).
- Argument lists count only at module level and in decorators. A call inside a
  component or hook body runs code and registers nothing.
- Statement calls count at module level and directly inside top-level functions.

**Unknown, never "missing".** A member is reported only when Drift can see every
place it could be registered:
- **Reachable lists count.** From the rule's list, Drift follows:
  - the other lists of the same call (`AppModule`'s `imports` next to its
    `providers`);
  - in each file a reached list names, that file's lists of the same call (an
    imported feature module, a `@Global()` module, a module in
    `forwardRef(() => M)`);
  - included urlconfs (`include("shop.urls")`);
  - routers mounted on mounted routers (`app.use(admin)`, then
    `admin.use(refunds)`).

  A member named by any of these is registered. In mining, only reachable lists of
  the rule's own kind count (providers through providers), and the fix names the
  nearest of them.
- **Lists of the same kind elsewhere count too.** A service provided by a sibling
  `@Module` that neither imports the other (twenty's
  `workspace-migration-runner.module.ts`) is provided by the app: never "missing",
  and never told to be provided a second time. In mining, a role whose members are
  split between such lists is not proposed against one of them (status `split`);
  the family of lists stands in, if it qualifies. A sibling list that is opaque
  does not make every member unknown (one `...providers()` anywhere would silence
  every rule): only the lists the rule reaches do.
- **Only lists the app has.** A list owned by a `@Module` that nothing imports and
  `NestFactory` does not bootstrap is dead: it is no sibling and no family member,
  so a service provided only there is reported (`LostService` in `LostModule`).
  Without a visible `NestFactory` call every module may be the root, and every
  list counts.
- **Outer lists count for inner ones.** A member that the list spreading a rule's
  list names directly (`providers: [...USE_CASES, Extra]`) is provided: not an
  outlier, never missing. It is not evidence for the inner list.
- **`DynamicModule`s.** An object literal with a `module` key returned anywhere
  in a file that imports from `@nestjs/common` (a `@Module`'s static method, an
  exported object's `forRoot()`, an arrow returning `({ module, ... })`) registers
  like `@Module({ ... })`: its `controllers`, `providers`, `imports` and `exports`
  arrays are lists of the decorator's slots.
- **`@Module(getModuleConfig())`:** a `@Module` whose argument is not an object
  literal has an opaque list in each of those slots, so their families are
  unknown.
- **A member provided only by a dead module** gets the fix "import `LostModule`
  from a reachable module" (`wire.action` `import_module`), not "add it to another
  module's providers".
- **Opaque lists say nothing.** A list is opaque (new fact `Registry.opaque`) when
  it holds what no reference describes:
  - a spread of a call (`...providers()`, in either function form);
  - a bare call naming nothing as an element (`provideHttpClient()`, a helper);
  - a function element or lazy route loader (`loadComponent`, `loadChildren`,
    `lazy`, `component: () => import(...)`);
  - a spread of a package's list, or of a constant bound to a call;
  - an `include()` Drift cannot place;
  - a Python lambda or `*helper()`.

  A list of nothing but these (`controllers: [...getControllers()]`) is kept as an
  opaque list with no items. It used to vanish from the facts, and its members
  looked unregistered.

  If any list that decides is opaque, the answer is unknown: `check` reports
  nothing, and mining reports the registry as `opaque` and never proposes it.
  Statement-call arguments (`app.use(cors(), (req, res, next) => ...)`) are not
  opaque: middleware factories and inline handlers register nothing.

**Rule.** For a role R, Drift uses structural roles at every depth with any entry
kind (`entry: "*"`), because entry kinds come from registration itself. A registry
G becomes a rule when all of these hold:
- G names at least 90% of R's members;
- R has at least 5 members, from at least 3 files, and the members G names come
  from at least 3 files (one module's names listed together are a module, not a
  registry convention);
- for a barrel, what a star re-export covers (`export * from "./a"`,
  `from .base import *`) counts only for a role inside the barrel's own directory.
  A star import re-exports one module; it is never evidence for a wider,
  package-wide barrel (pontoon's and Django-CRM's `settings/__init__.py`, which
  `from .base import *`, made every constant of the package "belong" there). In
  `check`, a barrel of star re-exports gets another star re-export as its fix
  (`` add `from .mail import *` to proj/settings/__init__.py ``), never a name.

A *family* of lists in one slot can stand in when no single list does. For example,
in cal.com the 109 of 110 services are spread over 50 `@Module` providers lists.
The message then names the nearest list (longest shared directory prefix).

**Choosing among candidates:**
- **Nested roles.** Of two nested roles, the broader one is kept only if the
  members it adds are themselves at least 90% covered. Otherwise the narrower one
  is kept.
- **Barrels.** One barrel per role, in the role's own package (the fullest, then
  the nearest). No "re-exported by some barrel" families.
- **Derived lists.** A list built from another list (`common = [...services]`)
  defers to the inner one.
- **Nested lists.** Of two proposed rules where one's list sits inside the
  other's lists (a list and the list spread into it, `include([...])` inside
  `urlpatterns`, a module and a module it imports, a family and one of its lists)
  and its role is the same or narrower, only that more specific rule is proposed.
- **Name narrowing.** When registered members share a name pattern that the
  unregistered ones lack, the rule is narrowed to it (`*Router`, `*Template`,
  `*_JOB_DEFINITION`).
- **Not members:** bases that other in-repo classes extend, abstract classes
  (Python, and TypeScript `abstract class`), protocols, registry bindings
  themselves, pseudo-symbols (routes, handler methods), the class or binding that
  owns the registry's list (`AppModule`, `appRouter`; for a family, an owner that
  no list of the family names: the root of the graph), and Nest root modules a
  file passes to `NestFactory.create*`.
- **Curated barrels.** A barrel is not proposed (status `curated`) when more than
  half of its outliers are internal: each imported directly, not through the
  barrel, by another production file of its own package, with nothing else in its
  file re-exported. Such a barrel is a chosen subset, and those outliers are
  internal on purpose (helpers its
  siblings share, a component kept out to avoid a name clash). Two exceptions keep
  real omissions: an outlier in a file the barrel re-exports from (ai's four new
  stream-part schemas next to exported ones), and a role of one kind (`*.output`
  files, a `*Template` name pattern), whose left-out member is an omission (a
  nested DTO), not a helper.
- **Caps:** 10 wiring rules per repo, at most 2 per role, ranked by Wilson lower
  bound × log2(1 + n).
- **Ids** hash the role and the rule without `reach`, which only describes how
  the rule was mined: a rule whose members move between its list and the lists it
  reaches keeps its id.

**Exclusions (autodiscovered members).** A role is not proposed when at least half
its members are wired by discovery. Its registries are reported with status
`autodiscovered:<why>`. In `check`, a discovered member is never reported.

| Class | Detected by |
| --- | --- |
| `file_routing` | the symbol is a Next.js route, page or layout. TanStack `createFileRoute(...)` lists are not registries |
| `glob_import` | the file matches an `import.meta.glob(...)` or `require.context(...)` glob (new fact `FileFacts.discovers`). Globs come from the repository, so they are matched with `globset` (an automaton, linear). A glob over 256 characters, 8 `{` or 16 `*`, or one `globset` rejects, discovers everything under its literal prefix: unknown, never missing |
| `di_auto_registration` | Angular `@Injectable({ providedIn })`, `typedi` `@Service`, `tsyringe` `@injectable`/`@singleton`/`@autoInjectable`/`@registry`, `inversify-binding-decorators` `@provide` |
| `framework_autodiscovery` | Django `admin.py`, `models.py`/`models/`, `migrations/`, `templatetags/`, `management/commands/`; Celery tasks when any file calls `autodiscover_tasks()` |

A list covering less than 90% is taken to cover a subset by design
(`below_threshold`).

**Legacy directories.** A directory that already holds a baselined violation of a
rule registers its members in a way Drift cannot see (`@Module(getConfig())`, a list
built at run time). So a new sibling there is not reported; a new member elsewhere
is.

## Co-change rules (git history)

Deliberately narrow. The only change mined is **keys added** (environment
variable names) to key files:
- dotenv templates only (`.env.example`, `.env.sample`, `.env.template`,
  `*.dist`, `.env.defaults`, `prod.env.example`). A real `.env`, `.env.local` or
  `prod.env` holds secrets: neither it nor its history is ever read;
- `turbo.json` (`globalEnv` and task `env`);
- TS/JS env schemas (`env.ts`, `env.server.mjs`, `server-env.ts`, `env/index.ts`);
- Python settings (`settings.py`, `settings/*.py`, `config.py`, `env.py`).

A commit qualifies for X when it adds keys to X (keys in `+` lines minus those in
`-` lines). The rule "keys added to X are added to Y" needs both of these:
- at least 90% of at least 5 qualifying commits added every one of those keys to Y;
- X and Y both exist now.

How history is read (a function of HEAD's commit id):
- **Walk:** `git log --name-only` over at most the newest 5,000 commits from HEAD
  (it stops at the commit `rev-list --skip=5000` names). Key files are matched in
  Drift, not with `:(glob)` pathspecs, which made git walk the whole history.
- **Patches:** `git log --no-walk -p --unified=0` of at most 500 of those commits
  that touched a key file, for those files only, as `:(literal)` pathspecs.
- **Bounds:** every git call has a 10 s wall-clock timeout (the process is
  killed; history `timeout`) and reads stdout through a pipe with a 32 MB cap
  (`too_large`).
- **Pinned:** user and system config cannot change the output. These are set on
  the command line: `diff.algorithm`, `diff.renames`, `diff.relative`, the diff
  prefixes, `color.ui`, `log.showSignature`, `log.decorate`, `log.follow`,
  `core.pager`, `core.quotePath` and `core.fsmonitor`. Also:
  `GIT_NO_REPLACE_OBJECTS`, `GIT_OPTIONAL_LOCKS=0`, no ext-diff, no textconv,
  `GIT_NO_LAZY_FETCH`.
- **Fails closed:** if git cannot say whether the clone is shallow, nothing is
  read.
- **Degraded states:** each gives no rules, never a guess:
  - a shallow clone (`history: "shallow"`);
  - a partial clone (`"partial_clone"`, detected by `remote.*.promisor` or
    `extensions.partialClone`: blobless clones would otherwise fetch from the
    network);
  - no git (`"no_git"`);
  - a failed, slow or oversized read (`"failed"`, `"timeout"`, `"too_large"`).

On a synthetic repository with 40,000 commits, `census --json` with the flag on
took 28–37 s before these bounds. It now takes 0.34–0.43 s (debug build; 0.10 s
with the flag off).

`check` compares the files as they are. A key of `from` that `to` lacks is a
violation at its line; legacy ones are baselined.

## Where it surfaces

- **`drift census` and `drift init`:** wiring proposals are appended after the
  ordinary ones, so existing ranks are unchanged. A `registry:` line names the list
  and a registered sibling, and a summary line reports registries seen and history
  status.
- **`drift check` and `drift review`:** the violation carries a `fix` line in text
  and a `wire` object in JSON, SARIF help and agent messages. Wiring violations
  never fail the check, also with `--strict` (the pre-commit hook and the action's
  `args: --strict`). One omission is one violation: a member missing from nested
  barrels, or from a list and the list spread into it, is reported once, for the
  accepted rule whose fix is nearest it.
- **End-of-turn hook (Stop):** the per-edit hook checks one file, and the registry
  is another file, so wiring is judged at the end of a turn. It never blocks or
  continues the turn:
  - **Only after edits.** PostToolUse records the files edited. Stop checks wiring
    only when one of them could be a member of an accepted wiring rule's role, or
    is a file the rule reads, and then checks only those files, on the cached
    scan. A turn without such an edit does no scan. On immich with 7 accepted
    wiring rules (debug build), an idle Stop took 1.1–1.4 s before and 0.015 s
    now; a Stop after a relevant edit takes 0.6 s.
  - **Advice, once.** A new, unregistered addition is shown to the person
    (`systemMessage`) and queued for the agent. The new `UserPromptSubmit` hook
    hands it over with the next prompt, once.
  - **Also when the Stop blocks.** If the same Stop blocks on another rule, the
    advice still goes out (`systemMessage` next to the block, and queued for the
    next prompt); it is never the reason to block.
  - **No one-file findings.** PostToolUse no longer reports wiring findings: a
    one-file scan cannot see the registries.
  - Without accepted wiring rules, the hooks behave exactly as before.
- **PR mode (`check --diff-base`):** a member in an added file or changed
  declaration, missing from its registry, is introduced. So is a key on a changed
  line of `from` that is missing from `to`.

## JSON (stable, additive)

See `docs/v2/wiring-sample.json` for a full synthetic sample. Every field is new;
none is present when the feature is off or the rule is not a wiring rule.

`census --json`:
- **`wiring`** (top level, only when enabled):
  - `enabled: true` and `params` (thresholds);
  - `registries[]`: `{path, line, slot, label, lists, role, role_summary,
    members, covered, status}`, where `status` is one of `proposed`, `subsumed`,
    `below_threshold`, `opaque`, `autodiscovered:<why>`, `split` (members are
    registered in other lists of the kind, which this one does not reach) and
    `curated` (a barrel of a chosen subset). At most 40 entries, proposed first;
  - `cochange`: `{history: read|shallow|partial_clone|no_git|failed|timeout|too_large,
    head, commits, rules}`.
- **`proposals[].wiring`** (wiring rules only): `{registry: WireHint, lists,
  history?: {head, commits, max}}`. `lists` is the family's size, or for a rule on
  one file the number of its lists in that slot (usually 1).
- **ids are unique** (one rule per role and rule).

`check --format json`, on each wiring violation:
- **`wire`**: a WireHint:
  - `action`: `register` | `reexport_module` (a barrel of star re-exports: add
    `export * from "./x"`, or `from .x import *`, not a name) | `import_module`
    (provided only by a module nothing imports, named in `like`: import it from
    the reachable module at `path`) | `mirror`;
  - `path`, `line`: the registry or target file, and the line its list starts (0
    for a barrel: export facts carry no lines);
  - `label`: `Module() providers`, `` `urlpatterns` ``, `re-exports`, `keys`, and
    so on;
  - `like`: `{name, line, path}`, a sibling already registered and the line it is
    listed at;
  - `entry`: `{symbol, path, line}`, what is missing.

### After the review

The review of #38 found six patterns where Drift said "not registered" while the
member was registered: a feature module imported by `AppModule` (and `@Global()`),
`forwardRef`, lazy routes, Django `include()` by string, Express sub-routers and
helper or nested spreads. Each is now a negative fixture, and each fails on the
reviewed binary. Re-running the same 22 repos:

| | before | after |
| --- | --- | --- |
| wiring rules proposed | 147 | 147 (127 unchanged, 20 replaced) |
| baselined violations (outliers of proposed rules) | 170 | 108 |
| rules that now say "directly or in the lists it reaches" | 0 | 11 |

What changed:
- **twenty and novu lose their family-wide DI rules** ("services in some
  `@Module` providers list"):

| Class | Example | Handling |
| --- | --- | --- |

| Duplicate registries | outer and inner barrel; `common = [...services]` | One barrel per role; derived lists defer to the inner one |
| Barrel families | "re-exported by some barrel" | Not a family: barrels count one by one |

### Self-check of proposed rules

The builder's own judgement of 52 wiring rules and an estimate of their
precision, first recorded here, were removed: they are not a study record, and no
blind label round has covered wiring rules yet (below).

### What blocks the default tier

- A blind label round (the study's three-way rubric) on wiring rules and on
  flagged new members.
- A corpus of agent-written diffs for violation precision. The bar is 90%, and
  barrels likely fall short without a "public API" signal.
- Co-change: more history-rich repos, rename following, and a docs target
  (`.md` tables of env vars), all left out here.

## Left out

- Docs as a co-change target.
- Rename following in history.
- Registries in YAML/JSON (`app.json` plugin lists).
- Registries Drift cannot see (computed configs, `@Module(getConfig())`). These
  are mitigated by the legacy-directory guard, not solved.
- Per-edit wiring advice: single-file checks skip wiring by design.
- A sibling list Drift cannot read fully (an opaque `@Module` elsewhere) does not
  make a member unknown; only the lists the rule reaches do.
- Star-re-export fixes are written without an extension (`export * from "./x"`),
  whatever the barrel's own lines use (`./x.js`).
- Public barrels whose internal helpers sit next to exported code (formbricks
  `chooseLanguage`, midday `computeChangeDescription`) are still proposed.
- Two disjoint roles on one list (immich's `*.command` classes and the other
  classes of `src/commands/**`, both in `commandsAndQuestions`) are two rules.
- A rule dropped as the less specific of a pair leaves its cap slot empty.
- Vendored copies outside a `vendor/` directory (novu's `py3dns`) are analysed,
  by every rule.
- Studio UI: the JSON is in place for the paired Studio PR.
