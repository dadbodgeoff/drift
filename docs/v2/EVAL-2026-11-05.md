## Quality of proposed conventions

Default settings (at most 15 per repo): twenty 15 proposals, cal.com 13,
formbricks 9, dub 9, documenso 5, excalidraw and create-t3-app none. Libraries and
template repos have no repeated structure, and Drift proposed nothing for them.
The builder's ratings of these proposals are not reproduced (see the note above).

### Examples

- **twenty:** resolvers use `AccessPolicyGuard` (133/144); DTOs are decorated
  with `@ObjectType` (402/406); exceptions extend `CustomException` (126/136).
- **cal.com:** API v2 controllers are decorated with `@UseGuards` (34/38) and
  pass `version` to `@Controller` (35/38).
- **formbricks:** server actions are wrapped in `actionClient` (117/119); EE
  actions pass `id` to `assertCan()` (50/58).
- **documenso:** tRPC procedures are wrapped in `authenticatedProcedure` or
  `adminProcedure` (204/232).
- **dub:** partner-profile routes are wrapped in `withPartnerProfile` (53/54).

### Remaining trivial classes

- Calls to an internal styling helper (`cn()`) in UI component folders.
- NestJS module files passing `providers`/`exports` to `@Module` (true of
  almost every module).

## Fixes made from this evaluation

| Problem found | Fix |
| --- | --- |
| `.js` files with JSX failed to parse (Docusaurus, React apps) | Plain JavaScript is parsed with JSX enabled |
| "Components call `useState`", "dialogs render `<Button>`" | Lift is measured against units of the same kind (components vs components), not the whole repo |
| Library calls and `use client` directives proposed with weak lift | External calls and directives need lift of 3.0 or more |
| `extend Base()` and "(files)" in rule text | Wording fixed |
